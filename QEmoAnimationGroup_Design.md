# QEmo Animation Group Design

## Goal

Upgrade QAnimator from a single animation bytes player into an animation group system similar to Spine animation workflow.

The target experience is:

```
QEmoGraphic
    |
    QEmo Animation Data
        |
        animations:
            idle
            open
            close
```

A user should not need to manage separate players for every animation.

---

# Decision

Use **one generated bytes file containing multiple named animations**.

Do NOT create one bytes file per animation as the main workflow.

Reason:

- Similar to Spine SkeletonData + Animation list.
- Easier for artists and designers.
- Avoid duplicated metadata.
- Easier animation switching.
- Better runtime management.

The current `.bytes` format should be extended instead of replaced.

---

# Encoder Changes

Current workflow:

```
video.mp4
    -> encoder
    -> animation.bytes
```

New workflow:

```
Animation Group

Input:

open.mp4
idle.mp4
close.mp4

Names:

open
idle
close

Output:

Chest.bytes
```

The generated bytes contains:

```
Header

Animation Count

Animation Table:

id
name
offset
length
duration
fps
frame info

Animation Data:

open frames
idle frames
close frames
```

# Encoder UI

The encoder should support an animation group list.

Example:

```
Animation Group Name:
Chest

Animations:

+ Add Animation

Name: open
Input: chest_open.mp4

Name: idle
Input: chest_idle.mp4

Name: close
Input: chest_close.mp4

Output:
Chest.bytes

[Generate]
```

The user controls both:

- animation name
- output bytes name

# Unity Runtime Changes

## QEmoGraphic

QEmoGraphic should support named animations.

Example:

```csharp
qEmoGraphic.Play("open");
```

The component internally finds the animation by name.

No external Player object should be required.

---

# Animation API

Required:

```csharp
Play(string animationName);

Play(string animationName, bool loop);

Pause();

Resume();

Stop();

Seek(float time);
```

Events:

```csharp
OnAnimationComplete(string animationName);
```

---

# Animation Switching

Support two ways:

## Immediate switch

Example:

```csharp
qEmoGraphic.Play("close");
```

Current animation stops immediately.

---

## Play after completion

Example:

```csharp
qEmoGraphic.Play("open", nextAnimation:"idle");
```

or through callback:

```csharp
qEmoGraphic.OnAnimationComplete += name =>
{
    qEmoGraphic.Play("idle");
};
```

# Test Requirement

Create a Unity test example using a treasure chest animation group.

The generated bytes should contain:

```
Chest.bytes

Animations:

open
idle
close
```

Test behaviour:

1. Play `open`.
2. When open finishes, automatically play `idle`.
3. Stay in idle for 5 seconds.
4. Play `close`.
5. After close finishes, restart the whole sequence.
6. Total cycle: approximately 10 seconds.

This test sequence can be implemented using UniTask in Unity code.

Example:

```csharp
async UniTaskVoid PlayChest()
{
    await qEmoGraphic.PlayAsync("open");

    qEmoGraphic.Play("idle");

    await UniTask.Delay(5000);

    await qEmoGraphic.PlayAsync("close");
}
```

# Do Not Implement Yet

Do not add:

- `.qemo` extension
- AssetImporter
- complex asset pipeline
- skeleton/bone system
- mesh deformation

Keep using `.bytes`.

First make the animation group workflow correct.

---

# Reference

The target user experience is similar to Spine Unity:

```
SkeletonGraphic
    |
    SkeletonDataAsset
        |
        Animation names
```

QAnimator equivalent:

```
QEmoGraphic
    |
    QAnimator bytes
        |
        Animation names
```

Learn Spine's workflow and Inspector experience, but do not copy Spine implementation.
